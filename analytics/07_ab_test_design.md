# A/B 테스트 설계 - Enhanced v2 기반 고객 이탈 방지 실험

> 이 문서는 실제 실험 결과가 아니라 **실험 설계안**이다. KKBOX 실서비스에서 캠페인을 집행하거나
> 결과를 관측하지 않았다. 문서의 고객 수, 이탈률, 재구독률, Lift는 2017년 Test 데이터에서 실제로
> 계산한 값이고, Treatment의 기대 효과와 MDE는 검증 전 가정이다.

## 1. 개정 배경

기존 문서는 피처를 2017-02-28까지 집계한 분석과 이전 LightGBM 결과를 기반으로 작성됐다. 그러나
`train.csv`는 2월 만료 고객의 사후 이탈 여부를 포함하므로, 2월 로그와 거래를 피처에 사용하면 만료
이후 행동이 포함될 수 있다. 이를 방지하기 위해 모든 피처 관측 종료일을 **2017-01-31**로 변경했다.

컷오프 변경 후 단일 피처의 Directional AUC는 다음처럼 달라졌다.

| 피처 | 변경 전 | 2017-01-31 컷오프 후 |
|---|---:|---:|
| `days_to_expire` | 0.905 | 0.590 |
| `days_since_last_txn` | 0.807 | 0.630 |
| `auto_renew_rate` | 0.752 | 0.749 |
| `last_is_auto_renew` | 0.748 | 0.746 |

만료·최근 거래 신호는 현실적인 수준으로 낮아졌지만 자동갱신 신호는 거의 유지됐다. 따라서 기존 문서의
"만료 임박"과 "장기 미결제" 중심 전략을 그대로 유지하지 않고, 최종 Enhanced v2 결과로 후보군과
실험 우선순위를 다시 계산했다.

## 4. 실험 A - 자동갱신 전환 지원 (1순위)

### 4-1. 선정 근거

- 자동갱신 OFF 고객의 이탈률은 32.46%로 전체의 5.08배다.
- 고위험과 자동갱신 OFF를 함께 만족하는 고객은 8,429명이며 이탈률은 49.01%다.
- SHAP 고위험 샘플의 85.8%에서 `last_is_auto_renew`가 가장 큰 양의 예측 동인이었다.
- 모집단 규모가 충분하고 자동갱신 설정 안내라는 실행 가능한 액션이 존재한다.

### 4-2. 가설

> 2017-01-31 시점에 고위험으로 예측되고 마지막 거래가 자동갱신 상태가 아닌 고객에게 자동갱신 설정
> 방법을 안내하면, 안내하지 않은 고객보다 향후 30일 내 재구독률이 높아질 것이다. 소규모 혜택을 함께
> 제공하면 안내만 제공한 경우보다 재구독률과 자동갱신 설정률이 추가로 높아질 수 있다.

### 4-3. 3-arm 설계

| 항목 | 내용 |
|---|---|
| 모집단 | `churn_proba >= 0.270839` AND `last_is_auto_renew = 0` |
| 과거 Test 기준 규모 | 8,429명 |
| 과거 Test 기준 재구독률 | 50.99% |
| Control | 기존 서비스 경험, 추가 안내 없음 |
| Treatment 1 | 자동갱신 설정 방법과 결제 예정일 안내 |
| Treatment 2 | Treatment 1 + 소규모 자동갱신 전환 혜택 |
| 배정 | 고객 단위 1:1:1 랜덤 배정, `revenue_tier`와 위험도 구간으로 사전 층화 |
| Primary KPI | 30일 내 재구독률 |
| Secondary KPI | 자동갱신 설정률, 안내 클릭률, 결제 성공률, 순증 매출 |
| Guardrail | 수신거부, 민원, 할인 비용, 취소율, 중복 메시지 노출 |
| 관측 기간 | 노출 후 30일, 필요 시 만료 후 30일까지 추가 관측 |

자동갱신은 고객의 명시적 동의 없이 설정하면 안 된다. Treatment는 선택권과 해지 방법을 분명하게
안내해야 한다.

### 4-4. 표본 크기

과거 Test 재구독률 50.99%, power 0.80, Control 대비 Treatment 2개 비교에 Bonferroni 보정
(`alpha=0.025`)을 적용한 두 비율 z-검정 근사값이다.

| MDE | 가정 Treatment 재구독률 | 그룹당 필요 표본 | 3개 그룹 총 표본 | Test 후보군 내 가능 여부 |
|---|---:|---:|---:|---|
| +3%p | 53.99% | 5,263 | 15,789 | 불가 |
| +5%p | 55.99% | 1,887 | 5,661 | 가능 |
| +10%p | 60.99% | 464 | 1,392 | 가능 |

Test 규모를 기준으로 하면 +5%p 이상을 탐지하는 설계가 현실적이다. 실제 운영 대상 규모와 최신
베이스라인이 달라질 수 있으므로 실험 시작 직전에 다시 계산한다.

## 5. 실험 B - 만료·결제 일정 정합성 지원 (2순위)

### 5-1. 선정 근거와 사전 점검

`expiry_alignment_gap`은 다음 계산식으로 만든 파생 피처다.

```text
days_to_expire + days_since_last_txn - last_payment_plan_days
```

마지막 결제일에 요금제 기간을 더한 예상 만료일과 실제 만료일의 차이를 뜻한다. 고위험이면서 절대 차이가
7일을 초과한 고객은 2,258명이고 이탈률은 76.53%였다.

다만 이 차이는 결제 오류뿐 아니라 정상적인 요금제 변경, 보상 기간, 취소 후 재결제 같은 정책에서 발생할
수 있다. 실험 전 결제 운영 담당자가 주요 발생 유형을 표본 감사해 "해결 가능한 일정 혼선"인지 확인해야
한다. 데이터 오류라면 고객 캠페인보다 데이터·결제 파이프라인 수정이 우선이다.

### 5-2. 가설

> 고위험 고객 중 요금제 기간과 만료 일정의 차이가 7일을 초과한 고객에게 현재 구독 상태, 만료일,
> 다음 결제 예정일과 셀프서비스 확인 경로를 안내하면, 안내하지 않은 고객보다 재구독률이 높아질 것이다.

### 5-3. 2-arm 설계

| 항목 | 내용 |
|---|---|
| 모집단 | `churn_proba >= 0.270839` AND `expiry_alignment_abs_gap > 7` |
| 과거 Test 기준 규모 | 2,258명 |
| 과거 Test 기준 재구독률 | 23.47% |
| Control | 기존 서비스 경험 |
| Treatment | 구독 상태·만료일·결제 예정일 안내 + 확인/수정 경로 제공 |
| 배정 | 고객 단위 1:1 랜덤 배정, `revenue_tier`와 gap 구간으로 사전 층화 |
| Primary KPI | 30일 내 재구독률 |
| Secondary KPI | 결제 정보 확인률, 결제 성공률, 고객센터 문의 해결률 |
| Guardrail | 문의 증가율, 취소율, 잘못된 일정 안내 건수 |

### 5-4. 표본 크기

과거 Test 재구독률 23.47%, power 0.80, 양측 `alpha=0.05`의 두 비율 z-검정 근사값이다.

| MDE | 가정 Treatment 재구독률 | 그룹당 필요 표본 | 2개 그룹 총 표본 | Test 후보군 내 가능 여부 |
|---|---:|---:|---:|---|
| +5%p | 28.47% | 1,204 | 2,408 | 부족 |
| +10%p | 33.47% | 316 | 632 | 가능 |
| +15%p | 38.47% | 146 | 292 | 가능 |

현재 규모에서는 작은 효과를 탐지하기 어렵다. 우선 운영 감사와 소규모 파일럿으로 메시지 정확성을
검증한 뒤, 여러 월 코호트를 누적해 표본을 확보하는 것이 안전하다.

## 6. 파일럿 C - 최근 미접속 고위험 고객 복귀

고위험이면서 관측 로그가 존재하고 마지막 로그 후 30일을 초과한 고객은 683명이고 이탈률은 88.87%,
재구독률은 11.13%였다. 위험 밀도는 높지만 규모가 작고 이미 이탈이 상당히 진행됐을 가능성이 있어
주 실험보다 탐색적 파일럿에 적합하다.

| 항목 | 내용 |
|---|---|
| 모집단 | 고위험 AND 로그 존재 AND `days_since_last_log > 30` |
| Control | 기존 서비스 경험 |
| Treatment | 과거 청취 기반 플레이리스트 + 복귀 메시지 |
| Primary KPI | 메시지 발송 후 30일 내 재방문 또는 재구독 |
| Guardrail | 수신거부, 앱 삭제, 메시지 피로도 |

과거 재구독률 11.13%에서 +10%p를 탐지하려면 그룹당 약 209명, 총 418명이 필요하다. 효과가 작을 경우
표본이 부족하므로 결과는 탐색적으로 해석한다.

## 7. 위험·월매출 세그먼트의 역할

가치 축의 실제 기준은 근사 LTV가 아니라 현재 월평균 매출이므로 `ltv_tier` 대신
`revenue_tier`, `고가치/저가치` 대신 `고월매출/저월매출`을 사용한다.

| 세그먼트 | 고객 수 | 실제 이탈률 | 활용 |
|---|---:|---:|---|
| 고위험/고월매출 | 5,617 | 52.43% | 상담·혜택 비용을 투입할 1차 ROI 우선순위 |
| 고위험/저월매출 | 4,639 | 55.18% | 저비용 자동 캠페인 우선 |
| 저위험/고월매출 | 69,125 | 3.68% | 충성도·장기 구독 관리 |
| 저위험/저월매출 | 69,559 | 2.12% | 일반 콘텐츠 추천·비용 최소화 |

고월매출은 이탈률이 높다는 뜻이 아니다. 처치 비용 대비 회수 가능한 매출을 판단하기 위한 층화·ROI
변수로 사용한다.

## 8. 공통 분석 계획

1. 고객 단위로 무작위 배정하고 최초 배정을 유지한다.
2. `revenue_tier`와 사전 위험도 구간을 층화 변수로 사용한다.
3. Primary KPI는 Intention-to-Treat 원칙으로 분석한다.
4. 두 비율 차이, 95% 신뢰구간, 상대 Lift를 함께 보고한다.
5. 3-arm 실험 A는 Control 대비 두 Treatment 비교에 다중비교 보정을 적용한다.
6. Secondary KPI와 세그먼트별 효과는 탐색적으로 해석하고 사후 선택을 실제 성과처럼 보고하지 않는다.
7. 실험 시작 전 모집단·MDE·표본수·기간·중단 기준을 사전 등록한다.
8. 실험 중간 결과를 반복 확인해 임의로 조기 종료하지 않는다.

## 10. 한계와 고도화 방향

- 수치는 2017년 단일 Test 코호트의 과거 결과이며 현재 서비스에 그대로 적용할 수 없다.
- SHAP과 집단별 이탈률은 인과관계를 증명하지 않는다.
- `expiry_alignment_gap`은 캠페인 전에 운영 정책과 데이터 품질 검증이 필요하다.
- Test 데이터를 본 뒤 정의한 세그먼트이므로 실제 배포 성능 검증에는 미래 코호트가 필요하다.
- train_v2를 사용할 수 있다면 미래 시점 외부 검증 코호트로 활용한다.
- 여러 캠페인 이력이 쌓이면 고객별 최적 처치를 예측하는 Uplift Modeling으로 확장한다.
- 일별 로그 시퀀스와 동적 스냅샷은 조기 이탈 신호 탐지를 위한 추가 고도화 과제로 남긴다.

## 11. 최종 권고

3. 만료 정합성 실험은 운영 감사 후 진행한다.
4. 최근 미접속 고위험 고객은 작은 파일럿으로 메시지 적합성을 먼저 확인한다.
5. 할인·알림 효과는 모델 점수가 아니라 A/B 테스트 결과로만 판단한다.
